`충족/적용`은 평가 당시 가이드의 5개 항목 중 해당 질문에 적용 가능하다고 판단한 항목만 분모에 포함한 기록이다. 현재 확정한 루브릭으로 다시 계산하지 않는다.

최종 회상 질문에 AI는 `음식 알레르기에 대한 정보가 제공되지 않았습니다.`라고 답했다. 전체 대화 방식에서는 같은 질문에 `땅콩 알레르기입니다.`라고 답했으므로, DB에는 원문이 남아 있어도 최근 3턴 밖의 사용자 제약은 현재 응답에 반영되지 않음을 확인했다.

## 6. 결론과 측정 한계

- 최근 3턴 제한은 DB의 전체 메시지를 삭제하지 않고 LLM에 전달하는 원문 범위만 제한한다.
- 6턴짜리 짧은 평가에서는 장기 대화 입력 토큰이 1.67%, 전체 입력 토큰이 0.87% 감소했다.
- 대화가 3턴을 초과한 뒤부터 프롬프트의 대화 원문 개수가 최대 3턴으로 제한되지만, 각 메시지 길이가 다르므로 요청별 입력 토큰이 완전히 동일해지는 것은 아니다.
- 입력 범위를 줄이는 것만으로는 최근 3턴 밖 사용자 정보를 유지할 수 없으며, 이번 알레르기 정보 미반영 사례가 누적 요약 도입 필요성의 근거가 된다.
- 모델 응답의 비결정성 때문에 `completionTokens`와 `totalTokens` 변화 전체를 최근 대화 제한의 효과로 해석하지 않는다.
- 이번 결과는 단일 6턴 시나리오 측정이므로 더 긴 실제 대화에서의 절감률을 직접 대표하지 않는다.
- `serviceDurationMs`는 HTTP 왕복 시간이나 사용자가 체감하는 TTFT가 아니다.
