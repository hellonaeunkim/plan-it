# AI 응답 근거 제한 규칙 v3 적용 결과

## 1. 측정 목적

기준선에서 확인된 근거 없는 시간 추정과 장문의 답변을 줄이기 위해 `ai-chat-v3`에 일반적인 근거 제한 규칙을 추가하고, 고정 평가셋 12건으로 토큰과 답변 품질 변화를 확인한다.

이번 측정은 일반적인 "추측하지 말라"는 규칙만으로 일정 데이터의 의미를 올바르게 해석할 수 있는지 검증하는 중간 실험이다. 공식 원본 결과는 [response-policy-539d293.json](../artifacts/response-policy-539d293.json)에 보존한다.

## 2. 변경 내용

`ai-chat-v3`에는 다음 동작을 시스템 정책으로 추가했다.

- 사용자 컨텍스트와 현재 질문에 명시된 사실만 확정적으로 답변
- 제공되지 않은 종료 시간, 소요 시간, 이동 시간을 추측하지 않음
- 정보가 부족하면 일정 가능 여부를 단정하지 않음
- 실행하지 않은 일정 저장, 수정, 예약 기능을 제공한다고 표현하지 않음
- 질문에 직접 답하고 요청하지 않은 표와 장문의 대안을 제한

일정 조회 범위와 이전 대화 범위는 변경하지 않았다.

### 5.1 해결되지 않은 시간 제약 문제

`time-constraint` 질문에서 모델은 다음과 같이 답했다.

> 12:30~15:00 사이에 약 2시간 30분의 여유가 있습니다. 따라서 오후 1시에 광화문광장을 방문하는 것은 현재 일정과 겹치지 않으며 충분히 가능한 시간대입니다.

DB가 제공한 값은 토속촌 삼계탕 `12:30`, 국립민속박물관 `15:00`이라는 방문 시작 시간뿐이다. 종료 시간, 체류 시간, 이동 시간이 없으므로 두 시작 시간의 차이를 그대로 여유 시간이라고 판단할 수 없다.

일반적인 추측 금지 규칙만으로는 모델이 도메인 데이터의 `방문 시간`을 시작 시간으로 해석하고, 그 사이의 가용 시간을 판단하는 것을 막지 못했다.

## 7. 결론과 후속 가설

`ai-chat-v3`는 출력 토큰과 장기 대화 입력 증가 속도를 낮췄지만 다음 두 목표를 달성하지 못했다.

1. 입력 정책의 고정 비용으로 전체 토큰이 8.58% 증가했다.
2. 시간 제약 질문에서 근거 없는 방문 가능 여부 단정이 유지됐다.

따라서 후속 프롬프트에서는 금지 사항을 더 나열하는 대신 데이터 의미와 응답 조건을 구체적으로 정의한다.

```text
일정의 방문 시간은 시작 시간이며 종료 시간이나 체류 시간을 의미하지 않는다.
종료·체류·이동 시간이 없으면 일정 사이의 여유 시간이나 방문 가능 여부를 판단하지 않는다.
사용자가 선호나 제약만 전달했다면 추가 조언 없이 한 문장으로 확인한다.
```

이 가설은 다음 프롬프트 버전에서 별도 측정하며, `ai-chat-v3` 결과와 구분해 기록한다.

## 8. 측정 한계

- 모델 옵션이 provider default이며 각 질문을 한 번씩 실행한 결과다.
- 모델 응답의 비결정성 때문에 토큰 변화 전체를 프롬프트 문구만의 효과로 단정할 수 없다.
- 품질 점수는 고정 루브릭에 따른 수동 채점 결과다.
- 현재 시간이 프롬프트에 포함되므로 기준선과 프롬프트 바이트가 완전히 동일하지 않다.
- `serviceDurationMs`는 HTTP 왕복 시간이나 사용자 체감 TTFT가 아니다.
