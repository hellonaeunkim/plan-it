# AI 프롬프트 정책·컨텍스트 경계 적용 결과

## 1. 측정 목적

시스템 정책과 사용자 일정 데이터를 하나의 `SystemMessage`에 혼합하던 구조를 역할과 경계 블록으로 분리한 뒤, 경계 문구가 추가한 입력 토큰의 고정 비용을 확인한다.

이번 측정은 토큰 절감 효과를 주장하기 위한 평가가 아니다. 정책·데이터 책임 분리와 컨텍스트 인젝션 방어에 필요한 고정 비용을 먼저 분리 측정해, 이후 일정 범위 제한과 최근 대화 윈도우의 절감량에 섞이지 않게 하는 것이 목적이다.

공식 원본 결과는 [prompt-boundary-e66b0dd.json](../artifacts/prompt-boundary-e66b0dd.json)에 보존한다.

토큰과 응답 원문은 평가 실행기가 자동 저장했고, 이 Markdown의 품질 판정과 설명은 평가 당시 적용한 기준에 따라 Codex가 응답 원문을 보조 검토해 작성했다. 평가에 사용한 Codex 모델·지시문·버전은 산출물에 기록되지 않아 정식 LLM-as-a-Judge 결과가 아닌 참고 자료로 취급한다.

## 2. 변경 내용

`ai-chat-v2`에서는 다음과 같이 프롬프트 경계를 변경했다.

```text
SystemMessage
└─ 변하지 않는 AI 역할과 행동 규칙

UserMessage / AssistantMessage
└─ 저장된 이전 대화

마지막 UserMessage
├─ <user_context>일정 데이터</user_context>
└─ <current_question>현재 질문</current_question>
```

- 일정 데이터는 더 이상 시스템 정책과 같은 문자열에 포함하지 않는다.
- 일정 데이터 내부의 `<`, `>`, `&`를 이스케이프해 경계 태그를 데이터가 조기에 닫지 못하게 한다.
- 프롬프트 버전을 생성 코드와 같은 `AIChatPromptFactory`에서 `ai-chat-v2`로 관리한다.
- 일정 범위와 대화 범위는 아직 변경하지 않았다.

## 6. 해석

정책·컨텍스트 경계를 적용하면서 입력 토큰이 715에서 761로 46토큰, 6.43% 증가했다. 이는 토큰 절감 실패가 아니라 다음 목적을 위해 추가된 고정 비용이다.

- 시스템 정책과 사용자 데이터의 책임 분리
- 일정 데이터가 시스템 지시와 같은 우선순위로 전달되는 문제 완화
- 사용자 데이터 내부의 경계 태그 위조 방어
- 실제 프롬프트 변경과 메트릭 버전의 연결

따라서 이 단계만으로 토큰이 감소했다고 표현하지 않는다. 이후 일정 범위 제한과 최근 3턴 윈도우를 각각 단독 적용하고, 이 46토큰을 포함한 상태에서 순 입력 토큰이 얼마나 감소하는지 측정한다.

## 7. 측정 한계

- 동일 질문 한 건을 한 번 실행한 결과다.
- 현재 시간이 프롬프트에 포함되므로 프롬프트 바이트가 기준선과 완전히 같지는 않다.
- 모델 옵션이 provider default이므로 생성 답변 길이와 응답 시간은 재실행 시 달라질 수 있다.
- 이번 측정은 경계 문구의 고정 입력 비용만 확인하며 전체 답변 품질을 대표하지 않는다.
- `serviceDurationMs`는 HTTP 왕복 시간이나 사용자 체감 TTFT가 아니다.
