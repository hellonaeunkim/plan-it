# AI 챗봇 프롬프트·컨텍스트 리팩토링 종합 결과

## 1. 목적

AI 챗봇에 전달하는 시스템 정책, 사용자 일정, 이전 대화의 책임과 범위를 단계적으로 조정하고, 각 변경의 토큰 사용량과 응답 변화를 고정 평가셋으로 확인했다.

모든 전체 비교는 같은 모델 `openai/gpt-oss-120b`, 평가 데이터셋 `ai-chat-eval-v1`, 독립 질문 6개와 장기 대화 6턴을 사용했다. 토큰 절감의 주
지표는 애플리케이션이 직접 제어하는 `promptTokens`로 한다.

## 2. 단계별 진행 결과

| 차수 | 프롬프트 버전 | 변경 및 확인 내용                                 | 측정 결과와 다음 결정                                                                                                       |
|-----:|---------------|---------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
|  1차 | `ai-chat-v1`  | 전체 일정과 전체 대화를 전달하는 기준선 측정      | 장기 대화 입력 증가율 `98.32%`와 근거 없는 시간 판단을 확인                                                                 |
|  2차 | `ai-chat-v2`  | 시스템 정책과 사용자 컨텍스트의 역할 및 경계 분리 | 경계 표현에 질문 1건 기준 46 입력 토큰이 추가됨. 안전한 데이터 경계를 위한 고정 비용으로 수용                               |
|  3차 | `ai-chat-v3`  | 일반적인 근거 제한과 간결한 답변 규칙 추가        | 한 차례 평가에서 출력 토큰은 16.99% 낮고 전체 토큰은 8.58% 높게 측정됐으며, 시간 차이를 방문 여유 시간으로 해석하는 응답이 남음 |
|  4차 | `ai-chat-v4`  | 방문 시각의 의미와 선호 전달 응답 방식을 구체화   | 한 차례 평가에서 v3보다 전체 토큰이 14.23% 낮게 측정됐고, 해당 평가 응답에서는 근거 없는 방문 가능 여부 단정이 나타나지 않음. 장기 대화 입력 증가율 `19.54%` |
|  5차 | `ai-chat-v5`  | 판단에 필요한 일정 시작 시각과 부족한 정보 안내   | 관련 일정 시작 시각은 보완됐으나 정보 부족 질문에 불필요한 일정이 연결되는 사례를 확인                                      |
|  6차 | `ai-chat-v6`  | 과거 일정 제외, 조회 기간 180일과 최대 3개 제한   | v5 대비 입력 토큰 12.34% 감소. 이번 평가에서는 일정 개수 상한이 발동하지 않아 기간 제한 효과만 측정                         |
|  7차 | `ai-chat-v7`  | DB 원본은 유지하고 LLM에는 최근 3턴만 전달        | 장기 대화 입력 토큰 1.67% 감소, 입력 증가율 `19.28% → 12.85%`. 최근 3턴 밖의 사용자 정보는 현재 답변에 반영되지 않음을 확인 |

단계별 Codex 보조 검토와 응답 원문은 [reports](./reports), 실행기가 자동 저장한 공식 수치는 [artifacts](./artifacts)에서 확인한다. 보고서의 기존 품질 점수는 단계마다 적용 항목이 일관되지 않았으므로 단계 간 정량 비교에 사용하지 않는다.

## 3. 전체 평가 토큰 비교

2차는 특정 질문 1건만 실행했으므로 아래 12개 요청 합계 비교에서 제외한다.

| 차수 | 프롬프트 버전 | promptTokens | completionTokens | totalTokens | 직전 전체 평가 대비 promptTokens |
|-----:|---------------|-------------:|-----------------:|------------:|---------------------------------:|
|  1차 | `ai-chat-v1`  |       11,551 |            2,407 |      13,958 |                           기준선 |
|  3차 | `ai-chat-v3`  |       13,157 |            1,998 |      15,155 |                          +13.90% |
|  4차 | `ai-chat-v4`  |       10,998 |            2,001 |      12,999 |                          -16.41% |
|  5차 | `ai-chat-v5`  |       11,176 |            2,581 |      13,757 |                           +1.62% |
|  6차 | `ai-chat-v6`  |        9,797 |            2,182 |      11,979 |                          -12.34% |
|  7차 | `ai-chat-v7`  |        9,712 |            2,328 |      12,040 |                           -0.87% |

`completionTokens`에는 사용자에게 보이는 답변 외에 모델 내부 추론 토큰이 포함될 수 있고 같은 입력에도 값이 달라질 수 있다. 따라서 출력 및 전체 토큰의 단계별
증감을 특정 문구 하나의 효과로 단정하지 않는다.

## 4. 2차 프롬프트 경계 비용

2차는 전체 평가가 아니라 기준선의 `specific-date-schedule` 질문 한 건만 같은 조건으로 실행했다.

| 구분          | promptTokens | 증감 | 변화율 |
|---------------|-------------:|-----:|-------:|
| 1차 해당 질문 |          715 |    - |      - |
| 2차 경계 적용 |          761 |  +46 | +6.43% |

46토큰 증가는 시스템 정책과 사용자 데이터를 분리하고 사용자 데이터 내부의 지시를 시스템 명령으로 취급하지 않도록 경계를 표시한 비용이다. 이 결과를 전체 평가의 토큰 증감률로
확대 해석하지 않는다.

## 5. 최초 기준선과 최종 결과

| 지표             |       1차 기준선 |                7차 최종 |                증감 |  변화율 |
|------------------|-----------------:|------------------------:|--------------------:|--------:|
| promptTokens     |           11,551 |                   9,712 |              -1,839 | -15.92% |
| completionTokens |            2,407 |                   2,328 |                 -79 |  -3.28% |
| totalTokens      |           13,958 |                  12,040 |              -1,918 | -13.74% |
| 장기 사용자 정보 | 전체 대화로 반영 | 최근 3턴 밖 정보 미반영 | 전달 범위 차이 확인 |       - |

고정 평가셋 기준으로 애플리케이션이 직접 제어하는 입력 토큰은 15.92% 감소했다. 단일 실행에서 전체 토큰은 13.74% 낮게 관찰됐지만 모델 응답 길이의 영향을 받으므로 직접적인 절감 성과로 사용하지 않는다. 가장 큰 입력 절감은 일정 조회 기간 제한에서 발생했고, 최근 3턴 제한은 짧은 6턴 평가에서 절감 폭은 작았지만 대화가 계속 쌓여도 매 요청에 전달하는 원문 개수를 제한하는 구조를 만들었다.

## 6. 최종 프롬프트 컨텍스트

현재 LLM 입력은 다음 순서로 구성한다.

```text
SystemMessage
└─ 역할, 응답 정책, 근거 제한, 사용자 데이터 경계 규칙

최근 대화 원문
└─ 현재 질문을 제외한 최근 3턴의 사용자 질문과 AI 답변

Current UserMessage
├─ 기준일부터 180일 이내의 일정 중 최대 3개
└─ 현재 사용자 질문
```

전체 대화 메시지는 삭제하지 않고 DB에 보존한다. LLM 입력에 포함할 때만 최근 3턴을 ID 기준으로 조회하고 과거에서 최신 순서로 전달한다.

## 7. 결론

이번 작업은 처음부터 최종 방식을 확정한 것이 아니라 다음 순서로 문제를 좁혔다.

1. 전체 일정과 전체 대화를 전달하는 기준선을 측정했다.
2. 역할과 데이터 경계를 분리하고 그 고정 비용을 별도로 확인했다.
3. 일반적인 응답 규칙을 적용한 뒤 부족한 사례를 실제 답변에서 찾았다.
4. 규칙을 구체화하며 토큰을 재측정하고 실제 응답의 변화와 남은 문제를 확인했다.
5. 불필요한 과거 일정을 제외해 입력 토큰을 줄였다.
6. 최근 3턴으로 원문 전달량을 제한하고, 범위 밖 사용자 정보가 현재 답변에 반영되지 않는 조건을 확인했다.

따라서 단순히 프롬프트 문장을 줄인 작업이 아니라, 변경 요인을 분리하고 같은 평가셋으로 재측정하면서 토큰 비용과 실제 응답 변화를 함께 확인한 리팩토링으로 정리할 수 있다.

## 8. 주요 성과 요약

> 시스템 정책과 사용자 컨텍스트를 분리하고 일정 조회 범위 및 최근 3턴 대화 윈도우를 적용했습니다. 동일 모델·고정 12개 요청 평가셋에서 입력 토큰을 15.92% 줄였으며,
> 저장된 응답을 평가 당시 적용한 기준에 따라 Codex가 보조 검토해, 해당 평가 응답에서 근거 없는 시간 판단이 나타나지 않게 된 과정과 남은 한계를 함께 기록했습니다. 최근 대화 범위 밖 사용자 정보가 현재 답변에 반영되지 않는 조건도 확인해 구조화된 누적 요약을 후속
> 개선 과제로 도출했습니다.

## 9. 후속 개선 과제

### 구조화된 누적 요약

최근 3턴 밖에서도 필요한 사용자 선호·결정·제약·미해결 사항만 구조화해 전달한다. 요약 호출 비용까지 포함한 순 토큰과 품질을 다시 측정해야 한다.

### 외부 LLM과 DB 트랜잭션 분리

답변 호출과 요약 호출 동안 DB 트랜잭션이 커넥션을 오래 점유하지 않도록 외부 호출과 저장 경계를 분리한다. 누적 요약 도입의 선행 작업으로 진행한다.

### 요약 안전장치와 운영 DDL

허용 필드 검증, 길이·개수 제한, 프롬프트 오염 방어, 동시 갱신 충돌 방지와 운영 DB DDL 적용 절차를 준비한다.

### SSE 응답 스트리밍

전체 응답 완료 시간과 별도로 사용자가 첫 글자를 받는 TTFT를 측정한 뒤 SSE를 적용하고, 동일한 클라이언트 조건에서 개선 전후를 비교한다.

## 10. 측정 한계

- 1차 기준선은 초기 터미널 출력이 아니라 이후 모든 비교가 참조한 공식 원본 `baseline-3c0c931.json`을 사용한다.
- 각 전체 평가는 모델 옵션을 provider default로 둔 단일 실행 결과다.
- 출력 토큰과 이전 AI 답변이 포함되는 후속 입력 토큰은 모델의 비결정성 영향을 받을 수 있다.
- 7차의 최근 대화 효과는 6턴 시나리오에서 측정했으므로 더 긴 실제 대화의 절감률을 직접 대표하지 않는다.
- `serviceDurationMs`는 HTTP 왕복 시간이나 사용자 체감 TTFT가 아니다.
- 응답 평가는 평가 당시 적용한 기준에 따라 Codex가 저장된 원문을 보조 검토한 참고 자료다. 평가에 사용한 Codex 모델·지시문·버전이 산출물에 기록되지 않아 정식 LLM-as-a-Judge 결과나 재현 가능한 자동 품질 지표로 사용하지 않는다.
- 기존 보고서의 합계 점수는 단계마다 적용 항목이 일관되지 않았으므로 단계 간 품질 개선 수치로 비교하지 않는다.
