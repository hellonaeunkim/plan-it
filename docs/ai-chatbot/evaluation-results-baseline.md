## 8. 관찰 결과

- 토큰 사용량: 전체 12개 요청에서 입력 11,551토큰, 출력 2,407토큰을 사용했다.
- 대화 누적에 따른 변화: 동일 채팅방의 promptTokens가 713에서 1,414로 증가해 첫 턴 대비 98.32% 증가했다.
- 연속 턴의 토큰 변화: 첫 알레르기 답변에서 completionTokens 587이 기록됐고, 직후 2턴의 promptTokens는 직전보다 501토큰 증가했다. 현재 메트릭은 응답 본문 토큰과 내부 추론 토큰을 분리하지 않으므로 두 수치의 일대일 인과관계는 단정하지 않는다.
- 일정 데이터 범위: 독립 질문은 질문과 무관한 과거·미래 일정까지 모두 전달받아 질문별로 712~730 promptTokens를 사용했다. 일정 범위 제한의 기여도는 이후 단독 측정한다.
- 답변 품질: 독립 질문은 16/18을 충족했다. 시간 제약 질문에서는 제공되지 않은 종료·이동·관람 시간을 생성하고 가능 여부를 단정했다.
- 장기 기억: 전체 대화를 전달하는 현재 방식에서는 다섯 턴 전의 땅콩 알레르기를 정확히 회상했다.
- 오류 및 재실행: 공식 측정 12개 요청은 모두 성공했다. 미커밋 상태에서 수행한 이전 측정은 Git 메타데이터가 실제 평가 코드와 달라 공식 비교에서 제외했다.

## 9. 측정 한계

- 공식 기준선은 한 번의 실행 결과다. 모델 옵션이 provider default이므로 같은 입력에서도 답변 길이와 후속 promptTokens가 달라질 수 있다.
- `serviceDurationMs`는 서비스 메서드 내부 시간이며 HTTP 왕복 시간이나 TTFT가 아니다.
- 현재 외부 LLM 호출은 DB 트랜잭션 안에서 실행된다. 따라서 이번에는 동시 요청이나 부하 테스트를 수행하지 않았다.
- 현재 프롬프트에는 실행 시점의 현재 시간이 포함되므로 완전히 동일한 프롬프트 바이트를 재현하지는 못한다.
